# 工作原理与安全边界

这份文档收纳 README 中不必让每位用户先读完的实现细节，包括 Manifest V3 请求切换、候选生命周期、测速参数和卡顿恢复。

## 作用范围

扩展只在 Manifest 中列出的 B 站播放路径运行：

- `www.bilibili.com/video/*`
- `www.bilibili.com/bangumi/play/*`
- `www.bilibili.com/cheese/play/*`
- `live.bilibili.com` 直播间（含 `blanc` 路径）
- 对应的部分移动端点播路径

目标媒体 host 必须通过 `*.bilivideo.com` 白名单校验。其他网站、其他媒体域名（包括 `*.mcdn.bilivideo.cn` P2P 节点）和非媒体请求不在切换范围内。

## 请求流程

1. `webRequest` 只读观察 B 站发出的 `bilivideo.com` 媒体请求，记录当前 host、Range、完成状态和错误。
2. 播放页主世界中的最小观察器克隆并解析 `playurl` 的 fetch/XHR 响应，以及页面已有的 `window.__playinfo__`。它只提取通过白名单校验的媒体 URL，不修改接口响应。
3. 隔离内容脚本使用当前视频签发的地址完成两阶段测速，以沿用播放器的页面来源与 Referer 环境。
4. 后台调用 `declarativeNetRequest.updateSessionRules()`，为当前标签页建立受限的 host 替换规则。

规则同时限制标签页、发起方、目标域名和请求类型。替换时只改变 scheme/host，原路径、查询参数与签名保持不变，因此播放器内部 Worker 的后续请求也可以在浏览器网络层命中。

## 候选来源与生命周期

每轮候选按以下顺序组合并封顶：

1. 当前视频实际请求的 host；
2. 当前 `playurl` 原样签发的 host；
3. 用户自定义项；
4. 少量核心冷启动种子；
5. 本机近期成功项。

扩展不接受协议、路径、端口或其他域名。动态学习记录最多保留 24 个，30 天后过期；长期失败或在真实播放中反复卡顿的项会逐渐降权。

这意味着新出现的 CDN 可以从实际播放中被学到，但候选列表和测速时间不会无限增长。

用户可以暂时禁用任意候选。禁用项、来源标签和历史成绩仍保存在本机并显示在弹窗中，但不会进入测速窗口、自动选择或卡顿恢复。若禁用的是当前重定向目标，会立即释放对应的标签页会话规则。

禁用不是网络黑名单。若该 host 恰好也是 B 站给当前视频签发的原始节点，扩展仍允许播放器在没有重定向规则时使用它，避免把正常播放直接拦断。

## 两阶段测速

- 初筛最多 8 个候选，每个读取最多 128 KB。
- 初筛最快的 3 个进入持续传输复测，每个读取最多 1 MB。
- 能识别当前播放接口的 DASH 轨道时，优先使用播放器实际请求的视频轨路径与对应 Range；只有捕获不到视频轨时才退回普通媒体样本。
- 单轮额外流量理论上限约 4 MB。
- 失败、超时、跨域拒绝或持续速度不足的候选不会被自动选中。

测速结果只代表当前视频、当前时间和当前网络路径。缓存、DNS 和跨境路由变化后，结果会重新评估。

## 直播模式

直播间复用同一套 DNR 会话规则机制，但边界与点播不同：

- 播放地址来自 `getRoomPlayInfo` / `getInfoByRoom` 响应和页面首屏数据，由主世界
  观察器把每个 `url_info` 的 `host + base_url + extra` 拼装成完整候选 URL。
- 直播流签名（`sigparams`）覆盖查询参数而不绑定主机名。路径中的
  `/live-bvc/<数字>/` 前缀是每次签发轮换的路由令牌，不是稳定的集群身份；
  真正标识一路流的是前缀之后的流名（含清晰度与编码后缀）。候选按流名
  匹配：同名不同前缀的签发地址互为可切换候选（实测同名分段跨前缀互通），
  不同协议或清晰度的流互不相认（跨流请求 404），点播 UPOS 种子对
  `/live-bvc/` 直接 403，因此直播不使用内置种子和学习记录。
- 切到同集群兄弟节点（路径完全相同）沿用单纯的 host 替换规则；切到
  另一次签发的集群时使用双规则：入口路径整体重定向到目标自己的完整
  签发 URL（签名随之替换），旧前缀下的其余请求（HLS 分段）按前缀映射到
  目标集群。分段文件名来自已被重定向的目标播放列表，两条规则配合后
  无论播放器以原始还是重定向后的地址解析相对路径，请求都落在合法路径上。
- 直播测速不依赖 Range：HLS 先取播放列表、解析最新同源分片再限量读取；
  FLV 直接读流并在样本上限处截断。整个探测在后台完成（直播边缘节点不校验
  Referer）。指向第三方中继域名的变体列表视为节点不可用。
- 直播优选结果只属于当前标签页的当前一路流，不读写全局缓存。播放器重连或
  切换清晰度会签发新路径，扩展检测到流族变化后清空结果、释放规则并重测。
- 直播会话规则额外带 `/live-bvc/` 路径过滤，只作用于直播媒体请求本身；
  测速优先使用每台主机自己的完整签发 URL（重复调用播放接口会轮换出
  新的主机对，各自带独立签名参数），换 host 仅作兜底。
- 点播的内置 UPOS 种子（COS/华为云/阿里云/腾讯云镜像）属于点播存储系统，
  实测对 `/live-bvc/` 返回 403，不带签名硬拼 gotcha 集群域名同样不可用，
  因此直播不使用静态种子。作为替代，触发直播测速时内容脚本会按
  60 秒冷却重放一次播放器自己发过的 playurl 请求（同参数 GET、最多两次、
  等同页面自身请求），收割 B 站轮换签发的其他集群并入候选池。
  扩展不构造新接口调用、不读取 Cookie 内容。
- 卡顿恢复沿用同一状态机，但不做一秒回退 seek，直接让播放器重连到直播沿；
  回退原始节点后，播放器重新拉流即触发新一轮候选发现。
- 预防性恢复在直播页使用独立阈值（`LIVE_OPTIONS`）：缓冲区间与净流出
  按秒级重标定、观察窗缩短，回补容差放宽到一个分段以上，
  避免 1 秒小分段的正常锯齿被误判为持续下降。
- FLV 长连接整场只产生一次网络事件，后台 service worker 空闲重启后
  无法靠 webRequest 重建观测。发现直播页流族为空时，扩展会通过页面桥
  向播放器查询它正在播放的流地址（`getPlayerInfo().playurl`），
  直接恢复观测与候选。
- 可选的"FLV 优先"档：一条会话规则把播放接口请求（`getRoomPlayInfo` /
  `getInfoByRoom`）的 `protocol` 参数改写为 `0`，让 B 站只签发 FLV 长连接流，
  再通过页面桥调用播放器的 `reload()` 立即生效。只改写自己浏览器发出的
  请求参数，不触碰响应内容。1 秒小分段 HLS 在高 RTT 链路上每段都付一次
  往返开销并反复经历 TCP 冷启动，同链路实测 FLV 长连接可稳定跟上实时；
  FLV 单连接对丢包型劣化更敏感，因此做成用户可选而非默认。
  这是唯一需要 `api.live.bilibili.com` host 权限的功能。
- 直播策略函数（流族识别、播放列表解析、候选过滤、探测规格）集中在
  [src/live-core.js](../src/live-core.js)，与点播的 `core.js` 纯函数层平行，
  两套端点语义互不渗透。

实测依据（主/备节点差距、签名跨主机通用性、协议族路径绑定）见
[docs/research/live-stream-lag-investigation-2026-08-18.md](research/live-stream-lag-investigation-2026-08-18.md)。

## 自动重新优选

| 档位 | 开始按需复测 | 结果硬过期 |
| --- | ---: | ---: |
| 积极 | 30 分钟 | 1 小时 |
| 平衡 | 90 分钟 | 2 小时 |
| 低频 | 6 小时 | 12 小时 |

所有档位都受同一组活动门槛限制：播放页可见、视频正在播放、确实出现媒体 Range 请求，并且当前至少还有 10 秒缓冲。扩展没有为这件事设置后台定时器。

## 卡顿恢复

自动模式下，扩展每 2 秒轻量读取一次播放器本地缓冲。只有页面可见、正在播放、前向缓冲降到 8 秒以内，并且最近至少 8 秒持续下降且没有明显回补时，才会提前尝试下一个已经通过测速的候选。暂停、切到后台或拖动进度条都会清空趋势记录。

如果趋势预警没有命中，播放器明确发出 `waiting` / `stalled` 后连续约 2.5 秒没有可播放缓冲，就会触发兜底；播放、拖动或跳转后的普通确认仍保留约 4.5 秒。相同 host 的两次恢复至少间隔 15 秒；切到不同 host 后使用 7 秒的短保护期，让新规则和播放器有时间发起首批请求，又不会让坏节点继承完整的 15 秒等待。后台还会按标签页串行处理恢复请求并执行同样的 7 秒下限，防止同一次卡顿的并发事件连续误切多个节点。

已经开始的请求无法半途迁移。规则更新后，内容脚本会把播放位置轻微回退并让播放器重新发起请求，因此可能出现一小段重复。

如果一轮候选全部失速，扩展会暂时回到 B 站原始签发节点，再做一次有上限的测速。重新选择时会暂避当前标签页里最近失速的 3 个 host，避免马上原路循环；这份记忆不会永久拉黑节点，手动重新优选或切换播放内容后会清空。

## 本地状态与清理

- 完整媒体 URL 只保存在当前后台/标签页的内存中。
- `chrome.storage.local` 只保存设置、host 和有上限的测速摘要，不保存完整 URL、签名、Cookie 或页面内容。
- 会话网络规则在离开播放页、关闭标签页、停用扩展或结束浏览器会话后移除或失效。
- 移除扩展会同时清除本地配置和学习记录。

## 权限边界

扩展不申请 `proxy`、Cookie、历史记录或 `<all_urls>` 权限。没有广告、分析 SDK、远程代码或开发者控制的服务器。
